# Skills: procedures the agent learns

A **skill** (*habilidad*; in the window, a **trade**) is a procedure that has already worked once, saved
so it can be repeated without thinking: the steps with their durable selectors, and whatever changes from
one time to the next turned into **parameters**. `faena do` looks at them before reasoning: if one matches
the goal, the model only picks it and fills in the values, the steps are replayed as they are, and the
model checks at the end that the goal has been met. In the notes app in `examples/`, "create a note" goes
from 30 s and 5 model calls to 13 s and 2.

## Where they live

One `.toml` file per skill in `%USERPROFILE%\Faena\habilidades\` (in a portable kit,
`<kit>\habilidades\`; `FAENA_HABILIDADES` changes the folder). They are plain text, meant to be read and
touched up by hand: rename parameters, refine `cuando`, remove an extra step.

## How they are created

`faena skills` is the same as `faena habilidades` (`list`/`lista`, `show`/`ver`, `learn`/`aprender`,
`import`/`importar`; `--name`/`--nombre`, `--description`/`--descripcion`, `--when`/`--cuando`, `--force`).

```
:: while doing a task: if it goes well, it is saved
faena do "Create a note titled 'Buy bread' with the text 'two loaves'" --url http://127.0.0.1:8770/index.html --learn crear-nota

:: from a task already done (its folder, or the folder's name inside Faena\tareas)
faena skills learn 2026-10-28-182652-crea-una-nota-con-titulo... --name crear-nota

:: from a process recorded in tramoya (by hand or by its AI): its id or its folder (the one with proyecto.json)
faena skills learn register-a-customer --name new-customer --when "new customer; register customer"

:: the ones tramoya learned when the agent lived there (%USERPROFILE%\Tramoya\habilidades)
faena skills import

faena skills list
faena skills show crear-nota
```

When learning:

- Each `escribir` (type) or `elegir` (choose) step is changed to use a parameter named after the field
  ("Type 'Buy bread' in the 'Title' field" → `title`), with that time's value as the example. If the field
  has no name, `texto`, `texto2`...
- Those values are also removed from the description ("Create a note titled '{title}'..."), so the model
  recognizes it with other values.
- `cuando` is built from the content words of the name and the description; it is worth refining with
  `--when "a; b"` or by hand.
- Steps removed in tramoya (`quitado = true`) and anything that is not an action are discarded; tramoya's
  narrator line (`texto`) is not kept.

## Format

The keys and step types are in Spanish: it is a data format, the same in every interface language.

```toml
nombre = "crear-nota"                     # required; also the file name
descripcion = "Create a note titled «{title}» with the text «{text}»"   # what the model reads to choose
cuando = ["create", "note", "jot down"]    # words or phrases that give it away in a goal
superficie = "web"                         # "web" or "escritorio" (desktop)
inicio = "http://127.0.0.1:8770/index.html"  # where it starts (url or program); `do --use-skill X` uses it if no --url/--app is given
origen = "tarea 2026-10-28-182652-..."     # informative
aprendida = "2026-10-28 18:27"             # informative

[parametros]          # name = example value
title = "Buy bread"
text = "two loaves from the bakery"

[[pasos]]             # in order; the same step format as tramoya projects
tipo = "clic"         # clic | señalar | escribir | elegir | tecla | ir | esperar
selector = "internal:role=button[name=\"New note\"i]"
desc = "Press the «New note» button"

[[pasos]]
tipo = "escribir"
selector = "internal:role=textbox[name=\"Title\"i]"
valor = "{title}"     # the {placeholders} are filled in valor, desc and selector
desc = "Type «{title}» in the «Title» field"

[[pasos]]
tipo = "clic"
selector = "#cookies-ok"
desc = "Press «Accept» (cookie banner: if it does not appear, it is skipped)"
opcional = true       # if it is not there, it is not a failure
```

Step types: `clic` (click), `señalar` (point at), `escribir` (type), `elegir` (choose), `tecla` (key),
`ir` (go to), `esperar` (wait).

- `selector`: on the web, any Playwright selector (the ones generated by the recorder or the agent, with
  frames `... >> internal:control=enter-frame >> ...`); on the desktop, the `uia=` format in
  [ESCRITORIO.md](ESCRITORIO.md). Required in `clic`, `señalar`, `escribir` and `elegir`.
- `valor`: the text to type, the option to choose (its visible text), the key (`Enter`, `Tab`, `Escape`...
  or as a person would say it: "Intro") or the url for `ir`.
- `desc`: for the report, for the recipe the model sees and for the guard: a `clic` whose desc names
  something irreversible ("Press the «Send» button") stops just as if the model had decided it. The descs
  generated by faena and tramoya end with the control's name between «».

## How they are used

1. **Candidates**: the ones on the same surface that share words with the goal (each `cuando` phrase that
   appears counts 2, each word of the name or the description 1, and starting in the same place adds 1).
   The best 3 are kept.
2. **Choice**: one model call with the candidates and their parameters; it answers
   `{"habilidad": "..." | "", "parametros": {...}}`. If none fits completely, it reasons from scratch. With
   `--use-skill X` there is no choice, but the values are still taken from the goal. `--no-skills` skips
   them.
3. **Replay**: each step with tramoya's step language (`Steps.RunAsync` on an `EscenaWeb`, at rehearsal
   pace), going through the guard against irreversible actions.
4. **Handover**: the model carries on with the recipe (the numbered steps, already with the values) in the
   prompt and the replayed steps marked as done. If everything was replayed, it usually just checks and
   says "finish"; if a step failed (the site changed), it takes over from there.

Without a model (`--use-skill X --no-model --param key=value`), only step 3: parameters that are not given
keep their example value, and it succeeds if all the steps are replayed.

The task report says which skill was used, with which values and how many steps were replayed.

## Exporting a skill as an Agent Skill

A learned skill can be turned into an *Agent Skill* of its own, so that Claude Code (or any agent that
reads `SKILL.md`) knows it exists and how to ask faena for it:

```
faena skill export crear-nota                     :: ~/.claude/skills/faena-crear-nota/SKILL.md
faena skill export crear-nota --scope project     :: .claude/skills/faena-crear-nota/ in the current project
faena skill export crear-nota --dir <path> --lang es --force
faena do "..." --url ... --learn crear-nota --skill   :: learn it and export it in one go
```

The `SKILL.md` of `faena-<name>` explains what the skill does, its parameters (with the example value) and
the exact command: `faena do "<goal>" --use-skill <name>`, or without a model `--no-model --param
key=value`; when it is worth letting the model check the end, and that anything irreversible still stops.
It does not overwrite an existing one without `--force` (which keeps a `.bak` copy). In the window,
**Teach me a new one** has an "Export as skill" checkbox and each trade has an export button.
`faena skill list` shows the ones faena has created. faena's general skill (`faena skill install`) is
described in the [README](../README.md#agent-skills).

## Limits

- A skill is linear: it has no conditions or loops. What really varies (a notice that sometimes appears) is
  marked `opcional`; the rest is handled by the model in the handover.
- The selectors are the ones from that time: if the site changes a lot, the skill fails early and the
  model does the rest; it is worth learning it again with `--force`.
- tramoya's `tramoya.toml` profiles (`direct` step lines) cannot be imported as skills yet.
